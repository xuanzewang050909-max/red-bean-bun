# C7 可重复启动展示版

方案名称仍为 **C7**。网页保持四张图；im0004、im0291、im0319、im0324 都是先运行原版，再手动运行改进版，标注“此图已专项优化”。列表不显示 nogt。算法、输入、位流及网页与封存的四图 r4 版逐字节一致。

## 首次放到板卡上

1. 确认之前任务正常结束、记录已保存；不要中断故障内核或强行关闭旧服务。
2. 打开当前板卡的 Jupyter 首页（原地址为 http://192.168.2.99:9090/，地址变动时用实际 IP）。新建文件夹 **c7_demo_r1**。
3. 上传 **C7_Demo_r1.zip** 和 **C7_Demo_r1.ipynb**，确认均完成上传。不要上传旧的板测 Operator Notebook 代替此文件。
4. 打开 **C7_Demo_r1.ipynb**。按顺序执行第一格“离线校验”、第二格“启动展示”；不要 Run All。第一格不访问硬件；第二格才加载已封存的 C7。
5. 第二格把 `AUTHORIZED=False` 改成 `True`，仅在确认板卡空闲后运行。打开它打印的 **http://板卡IP:8090/**，保持 Notebook 内核运行。

## 网页怎样展示

1. 选择 im0004、im0291、im0319 或 im0324；配置 **C7 / 512×512 / 最终掩膜 / 阈值112**。
2. 点 **① 运行原版 C7**，等四张图出现。这时展示原C7真实输出。
3. 点 **② 运行改进版 FPGA**，等完成后查看专项补标。计算仍在 PL 上，不播放预存答案。
4. 完成后用 **查看原版 / 查看改进版** 切换。切换已有结果不重新运行 FPGA；两次计算完成后可快速对比。切到另一张图时按1～3操作。
5. 页面仅显示原始眼底、FPGA增强、血管候选、血管叠加四个面板。其他图仍走原流程。

此版解决重复启动管理，不声称加快算法。专项补标仍需等待实际 FPGA 运算，未设响应时间门槛。

## 正常结束与下次启动

- 本轮全部操作完成后，回 Notebook 执行第三格 **保存记录并正常结束**，下载显示的 ZIP。运行中或故障时该格会拒绝关闭，不复位、不释放故障缓冲。
- **同一开机期间再展示：** 正常结束后再次执行第二格，就会新建会话；不需要删文件或重启内核。重复点击正在运行的启动格只返回原网页地址，不重复加载。
- **下次开机再展示：** 打开同一份 Notebook，执行第一格和第二格即可。不必重新上传、解压或删除记录。记录使用独立编号永久留存。
- 正常结束网页服务不等于 Linux 关机。需要断电时按板卡原有正常关机步骤操作，避免直接断电损坏 SD 卡。
- 每轮沿用原100个请求及磁盘余量限制，达到限制后正常结束再开新轮。磁盘不足会停止，程序不自动清理历史。

## 异常时

端口占用、超时、断连或核验错误：保存提示，不杀进程、不强制重载。若只是网页关闭但 Notebook 内核正常，可以重新打开8090页面；不要重跑正在执行的图像请求。

同一次开机中，若内核已丢失而旧会话未正常结束，展示器会拒绝创建新硬件会话。它不能确认未知在途事务安全，不提供“强制重试”。内核仍可用且硬件调用已返回时，可用第四格只导出现有记录。故障处理后如何恢复需按实际现场判断，不能为绕过保护强行断电。

`demo_runtime/app/browser_results/` 保留原框架完整会话；`demo_runtime/demo_attempts/` 保留每次启动、结束与独立导出。若跨开机后有原启动失败文件，会原字节转存到新启动记录，并记录原路径与SHA，不删除失败证据。

## 验证边界

本次仅在开发电脑核验包身份和重复启动/正常结束/故障保护流程，使用硬件替身；没有连接板卡、加载位流或运行图像。展示版实际生命周期板测为 **NOT_RUN**。已沿用的算法历史板测证据保持不变。
