# W4c：独立纯DMA正式测量协议

2026-10-16，用户已将顺序调整为可信C7系统工作先行。W4.1已独立核验；W4b用户提供完成截图，下载原件尚未定位，仍需完整审查。本轮独立准备，不把截图补成通过证据。

使用既有可信A0 r2小型回环overlay：DDR→MM2S→AXIS FIFO→S2MM→DDR。原2017.4时钟、复位、标准IP、HWH、bit均不变；不重建、不修改C7，不把C7 mode0当纯DMA。该硬件在2026-10-11完成短包与70次正确性测试，新测试仅新增正式分组计时和完整原始数组回收。旧正确性结果不代替新测量。

固定协议为17字短包一次，然后256×256与512×512，各3轮，每轮3次预热＋100次计时，合计619次、101,253,137个32位字。每次输入为`uint32(arange(N)) XOR uint32(sequence*0x9e3779b9 mod 2**32)`，全程唯一递增序号，接收缓冲预置反码。每次保存真实RX完整NPY并逐字比对；失败停止，保留缓冲及输出。不按图像显示选择样本，不舍弃慢帧。

原Notebook嵌入的A0辅助函数保持原字节，继续调用PYNQ 3.0.1原生allocate、DMA transfer/wait/stop。辅助脚本SHA为26d3dda2d0d4f42cccf72927fa339f705b27ca7d35cb2a4e79f2b0fd053cc3d7；历史manifest中Windows源码SHA不同，是Notebook内LF规范化差异，不能声称二者原始文件字节相同。

计时采用板端同一`perf_counter_ns`：

| 指标 | 范围 |
|---|---|
| transaction_ns | recv.transfer之前→两路官方wait返回之后；包含TX flush、驱动调用、等待轮询与RX invalidate |
| submit_to_observed_idle_ns | recv.transfer之前→原A0辅助函数观察到两路IDLE；仍含提交和TX flush，不是纯AXI周期 |
| wait_invalidate_ns | 观察IDLE→两路wait返回；包含官方RX invalidate |
| snapshot_ns | 两路wait返回→普通CPU数组复制完成 |

分配、生成输入、预填反码、RX预flush、核验、数组落盘、JSON记录不在transaction范围。原A0辅助函数每1ms轮询，会产生观测量化和调度开销；本轮接受这一已验证实现，不擅自改成自定义DMA驱动或虚报总线内部精度。数据吞吐为每次双向`2*N*4`字节/平均transaction，明确称双向有效载荷吞吐；不可称C7端到端FPS，不可从C7事务减去C7核心时间得到此数值。

只有两尺寸各300计时样本＋18预热＋短包全部完成且一次加载、无错误、无保留缓冲、两路空闲后，才停止DMA并导出。旧8090服务仍运行、目录重复、空间低于2GiB、包字节不配对会在加载前阻止测试。错误或超时不自动重试、重置、重载；MMIO总线本身卡死时Python截止时间无法解锁，用户保留现场。

独立回收脚本核对发布身份、七框源代码与执行顺序、每次原始数组/长度/地址/状态/纳秒时间边界、分组统计和关闭状态。HOST替身被明确拒绝；构造的解析器正例不属于真实板测。当前`BOARD_NOT_RUN`，没有新增FPS/时延或质量结论。
