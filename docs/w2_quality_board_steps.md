# W2 + Q2：亮区误检候选与硬件参数、计时板测

本轮在 W1 浏览器基线之后、W3 新算法浏览器整合之前，复用已测 A4 的 PS、DDR、AXI DMA、GPIO、FIFO、官方 PYNQ 驱动。新增 PL 双侧支持 C2、真实可调阈值和帧内锁存参数、核心周期回读。**不需要 HDMI。**

本轮先用浏览器中的 Jupyter 核对新 PL；原 8090 界面不会自动切换新算法。W3 才把已板测的新模块接入交互界面。C2 是训练阶段冻结的候选，仍可能保留亮区误检；不能提前保证所有亮边消失或总体精度达标。

## 上传与运行

1. 上一轮 `browser_start.ipynb` 已正常打印 `BROWSER_SERVICE_CLOSED_IDLE` 后，在 Jupyter **Running** 页关闭其已完成内核。若仍有服务运行，先在无任务、`IDLE` 时运行原正常关闭框；不要对 FAULT/在途失败内核这样操作。关闭旧 8090 应用标签，避免同时控制 FPGA。
2. 新建文件夹 **retina_quality_w2_r1**，上传 `D:\PLD\retina_fpga\build\deploy\w2_quality_2017_4_r1` 中**全部 11 个文件**。不要覆盖旧 A4/W1 文件夹，也不要混入旧 bit/HWH。
3. 打开 **w2_quality_check.ipynb**。依次选中代码框、按 **Shift+Enter**；当前框变成 `In [数字]` 且无报错后再继续，不要点 Run All。

|代码框|完成标志|
|---|---|
|1：准备函数|`In [数字]`，无报错；没有打印正常|
|2：核对文件|`W2_PRECHECK_PASS`，FPGA 尚未改变|
|3：只加载一次|`W2_LOAD_PASS`，驱动、实际时钟、观测器和复位状态通过|
|4：单帧验证|`W2_SMOKE_PASS`，一帧 256×256 逐字匹配|
|5：原算法回归|`W2_BASELINE_PASS`，连同前一步共 61 帧原算法|
|6：C2 与真实改参|`W2_CANDIDATE_PASS`，新增 19 帧；累计 80 帧|
|7：对比实际结果并打包|显示上下两排图，打印 `W2_RESULTS_READY`|

第 6 框验证 A/C2 切换、256/512、处理阶段，以及阈值 **1、27、28、29、255**。每帧都重新送入 PL，并回读实际锁存参数、帧号和硬件周期；原算法基线仍固定 T=28。

第 7 框**上排 A、下排 C2**，都使用同一 im0001、512×512、T=28。四列依次为原绿色、增强、血管掩膜和叠加，图片只从已逐字核验的真实 DMA 输出读取。预计算参考文件仅作比较，不参与显示。

4. 按 **Ctrl+S**。通过 **File → Download as → Notebook** 下载运行后的 **w2_quality_check.ipynb**。
5. 回文件列表，下载 **w2_results_bundle.zip**。可同时保存第 7 框对比图截图。两份下载后反馈“已下载”。

红色报错，或一分钟没有新进展：**停下并保留输出，不重复运行、不关闭失败内核、不重载 Overlay 或手动释放缓冲**。失败记录同样保留。

## 记录边界

80 帧共 13,303,808 个输出字。每帧记录真实数组、输入/输出哈希、收发字节、实际锁存参数、帧号、核心/输出排空/输入空等/输出背压周期、PS 原始时间戳。实际 FCLK0 寄存器回读必须为 100 MHz。

- PL 核心帧时间从 HLS 首输入握手到末输出首次有效，包含过程中的流式等待。
- DMA 事务窗口包含 PL 重叠；**不能相减构造纯 DMA 搬运时间**。
- 本轮完整推理诊断窗口从参数配置到 DMA 完成后的普通 CPU 快照结束，不含输入读取/分配、校验、导出。
- 浏览器绘制延迟/FPS、独立纯搬运、正式 CPU 对照、全 20 图两尺寸 AH/VK 质量、长时稳定性等在 W3/W4+Q3/W5 继续，不由本轮代替。

发布包状态 `NOT_RUN` 是发布时真实状态，后续板测另外归档，不篡改发布 manifest。收到结果后，使用 `scripts/verify_w2_board_results.py` 逐字复核 80 帧、预览像素、真实参数、计时原始边界和执行 Notebook，再评价亮区变化。
