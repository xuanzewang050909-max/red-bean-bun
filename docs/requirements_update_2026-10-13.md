# 2026-10-13 项目展示与实验方案变更

状态：用户正式授权的当前要求。实验和最终现场均采用 **PYNQ-Z2 + 以太网 + Windows 笔记本浏览器**。本文替代原任务书及早期计划中强制 HDMI、VDMA 视频输出和先完成 HDMI 再迁移的要求；[原始任务书](original_development_task.md)、原代码、发布包和实测证据保留。当前架构见 [vivado_architecture.md](vivado_architecture.md)，执行顺序见 [browser_development_plan.md](browser_development_plan.md)，验收见 [browser_acceptance.md](browser_acceptance.md)。

## 用户原始调整通知

> **项目展示方案调整通知：** 根据《东南大学第二十届 PLD 设计竞赛》题目一的要求，现正式确定采用 **PYNQ-Z2 FPGA开发板 + Windows笔记本电脑 + 浏览器交互界面** 作为最终现场展示方案，**不再将外接HDMI显示器及HDMI视频输出链路作为必须实现的功能**。具体要求如下：① FPGA的PL端必须实际完成医学影像增强、眼底血管分割及相关核心处理任务，禁止使用CPU计算结果冒充FPGA输出；② PS端负责图像读取、DDR缓存、DMA传输、参数配置、结果获取以及与电脑的网络通信；③ Windows电脑通过以太网访问PYNQ-Z2，使用浏览器展示原始眼底图像、增强图像、血管分割掩膜、血管叠加效果、血管面积占比、Dice/IoU、实际FPS、处理延迟及FPGA运行状态；④ 界面必须支持图像切换、分割阈值调整、算法模式选择和结果导出，相关操作应真正作用于FPGA处理流程，而不是仅改变静态图片；⑤ 优先复用PYNQ-Z2官方Base Overlay、板级原理图、现有AXI DMA/DDR通路、PYNQ驱动及相关Demo，避免重复开发基础功能；⑥ 由于不再强制实现HDMI输出，应优先采用精简的自定义Overlay，将节省的FPGA资源和开发时间投入血管分割准确率、硬件加速、系统稳定性和交互体验；⑦ 开发过程中必须使用真实PYNQ-Z2进行板级测试，记录性能、资源占用及算法精度，不得虚构测试结果；⑧ 最终提交完整Vivado工程、RTL源码、PYNQ驱动、浏览器界面、设计报告及演示视频。**请据此更新现有项目架构、开发计划和验收标准，保留已经完成且可复用的功能，不要推倒重来。优先保证“真实FPGA计算 + 浏览器实时交互 + 完整性能验证”的稳定闭环。**
>
> 实验阶段也正式取消 HDMI 显示方案，统一使用 **PYNQ-Z2 + 以太网 + Windows电脑浏览器交互界面**，不需要先实现HDMI输出再迁移。请立即据此调整实验架构：保留真实的FPGA图像增强、血管分割、AXI DMA、DDR缓存和PS/PL通信；通过PYNQ端Python服务将FPGA实际处理结果传输到浏览器，支持原图、增强图、血管掩膜、叠加结果、算法评价指标及性能数据展示，并可交互修改FPGA算法参数。实验必须分别测量FPGA核心处理时间、DMA传输时间、完整推理时间以及浏览器显示延迟。优先复用官方PYNQ-Z2相关Demo和现有工程，不再为HDMI开发专用模块，也不要重建已经完成的可复用部分。所有算法精度与硬件性能实验保持原有设计，确保核心计算真实发生在PL端，并在真实开发板上验证。
