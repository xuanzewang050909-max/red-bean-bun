# B 排版缓存对比操作步骤

本次缓存固定标题，并复用普通 NumPy 画布和像素暂存数组。显示仍使用原官方 VDMA 的 newframe/writeframe；冻结算法、bit/HWH、驱动和输入均不变。新包发布时板测为 NOT_RUN，提速为 NOT_MEASURED。已完成的 B 370 帧和分段诊断不重跑；本次仅做一次新旧排版对比。

1. 打开 Jupyter 首页：`http://192.168.2.99:9090/tree`。保持供电、网线，显示器接板上 **HDMI OUT**。在 **Running** 页关闭之前已经成功完成的测试内核。若仍有未恢复的 DMA 错误，保留失败内核和输出，先反馈。
2. 新建文件夹，命名 **retina_b_layout_r1**。把电脑 `D:\PLD\retina_fpga\build\deploy\b_layout_2017_4_r1` 中的 **全部 18 个文件**上传进去，完成列表中的 Upload。本次只打开 **b_layout_compare.ipynb**，包内另一个旧 B Notebook 仅用于核对来源。
3. 按下面表格依次运行 **7 个代码框**。每框只运行一次：选中框，按 **Shift+Enter**，等左侧 `In [*]` 变成 `In [数字]` 且无红色错误，再进入下一框。不要使用 Run All。

|代码框|预期结束标志|操作与观察|
|---|---|---|
|1：准备函数|`In [数字]`，无错误|导入完成即可；不打印是正常的。|
|2：检查文件和普通画布|`B_LAYOUT_PRECHECK_PASS`|核对两份 Notebook 的代码、脚本和固定文件，检查整幅画布像素。缓存约 7.3 MiB 普通 CPU 内存；本框不加载 FPGA、不分配 DMA/视频帧。|
|3：加载一次|`B_LAYOUT_LOAD_PASS`|加载原 B bitstream 一次，保持同一工程。|
|4：短帧和显示准备|`B_LAYOUT_HDMI_READY`|先校验一帧 256×256 算法输出，再启动原 HDMI。显示器应有蓝、绿、红彩条和白色边框、十字线。确认画面正常后继续。|
|5：真实输出像素一致性|`B_LAYOUT_PIXELS_PASS`|校验一帧真实 512×512 FPGA 输出，新旧排版在 3 个标记位置整幅 720p 逐像素一致。显示器切到左侧原图、右侧绿色候选叠加。|
|6：两组对比计时|`B_LAYOUT_COMPARE_COMPLETE`|先原排版，再缓存排版；每组 3 帧预热、30 帧计时，每 5 帧打印 `B_LAYOUT_PROGRESS`。两组都结束后打印排版毫秒数和完整核验循环 FPS。白色标记随帧移动，两组结束画面相同。|
|7：关闭并打包|`B_LAYOUT_RESULTS_READY`|保存记录、关闭官方显示并打包，网页显示缓存组最后一帧预览；显示器变黑或无信号是预期。|

4. 运行完第 7 框，按 **Ctrl+S**。通过 **File → Download as → Notebook** 下载运行后的 **b_layout_compare.ipynb**。
5. 回到同一文件夹列表，下载 **b_layout_bundle.zip**。这份 ZIP 含原 JSON、真实 FPGA 数组和彩条/新旧排版 PNG。两份文件下载到 Windows 后反馈“已下载”；项目再独立复算像素、原始时间、帧计数和提速比例。

任何代码框出现红色报错，或一分钟没有新进展，保存输出并停止，反馈报错文字。不要重复运行、释放缓冲、切换 Overlay、运行最后的关闭框或重启失败内核；可能在途的缓冲引用会保留。两份 Notebook 正常保存允许改变输出、日期和 Markdown；执行代码仍严格校验。

两组均保留完整算法收发、逐字比较、字节数与 FPGA 帧计数、排版、官方帧分配/复制/缓存刷新/中断等待/提交、视频状态、输出哈希、进度记录。66 个比较帧加 2 个前置帧，共 68 个算法帧。输入不含 GT；不修改阈值或分割结果。

缓存初始化耗时单独记录。每组计时排除文件读取、参考生成、首次算法缓冲分配、3 帧预热和最后 PNG/JSON/ZIP 保存；完整循环含计时簿记开销。采用固定输入、固定顺序“原版→缓存版”，测量的是这次相同核验负载的两组循环；板上旧日期保留，耗时用 perf_counter_ns。实际改善须等下载记录核验后确认；这些 FPS 不代表 SD 输入到屏幕延迟、纯 PL 性能或显示扫描频率。
