# 项目开发任务书：RetinaFPGA

## 1. 你的身份与总目标

你是一名熟悉 AMD/Xilinx Zynq-7000、Vivado、Verilog/SystemVerilog、AXI4-Stream、AXI DMA、PYNQ Linux、数字图像处理的 FPGA 开发工程师。

请开发一个能够部署到真实 PYNQ-Z2 开发板上的医学影像实时分析与智能辅助展示系统。

**硬件平台：**
- 开发板：PYNQ-Z2
- SoC：XC7Z020-1CLG400C
- RAM：512MB DDR3
- FPGA工具：优先适配 Vivado 2022.2，若实际环境不同须检测并调整
- 运行环境：PYNQ Linux
- 图像处理核心语言：Verilog/SystemVerilog
- 控制和交互：Python

**医学任务：**
基于 STARE 公开数据集进行视网膜血管提取、图像增强、血管分割、面积比例计算和辅助可视化。

项目面向东南大学第二十届PLD设计竞赛题目一。

目标必须是真实FPGA部署，而不只是一个Python图像处理Demo。

## 2. 强制原则

1. 核心医学图像处理与血管分割必须在FPGA的PL侧运行。
2. PS负责文件读取、参数配置、控制、界面和结果保存。
3. 可以使用CPU建立算法参考模型，但最终不能用CPU生成结果冒充FPGA分割。
4. 禁止在没有编译和板级测试的情况下声称FPGA已经运行成功。
5. 禁止虚构FPS、Dice、IoU、资源利用率、时序或功耗数据。
6. 禁止用人工标注掩膜作为FPGA算法输入来伪造分割效果。
7. 不要直接套用其他型号开发板的引脚约束文件。
8. 全部核心代码、构建脚本、测试、接口文档必须保存在Git项目中。
9. 所有软件参考算法都要提供对应的可复现测试。
10. 每完成一个阶段，输出验证记录、存在问题及下一步工作。

## 4. 数据集处理

使用STARE官方数据集。

完成：
- 读取原始700×605 RGB眼底图像。
- 读取对应人工血管分割标签。
- 保存原始文件和样本ID之间的对应关系。
- 等比例缩放到512×512，使用padding保持纵横比。
- 对分割标注使用最近邻插值。
- 生成有效眼底区域FOV掩膜。
- 保持RGB/BGR通道顺序一致。
- 提供256×256快速调试模式。
- 记录处理前后坐标映射。

数据预处理使用Python。

提供单元测试，确保图像、FOV和血管标注严格对齐。

不要将测试图像的人工标注泄漏进分割算法输入。

## 5. 软件算法原型

首先使用NumPy/OpenCV实现两种候选方法。

算法A：
- 提取绿色通道
- 3×3高斯滤波
- LUT对比度增强
- 局部背景差分
- 二值阈值
- 形态学去噪
- FOV过滤

算法B：
- 包含算法A的基础模块
- 引入4方向线状血管特征增强
- 使用7×7范围内的稀疏定点滤波或其他合理设计
- 多尺度响应融合可作为后续优化项

请在软件阶段验证哪个方案更适合硬件化。

所有定点操作需要明确：
- 位宽
- 系数
- 舍入方式
- 溢出和饱和处理
- 边界策略
- 中间结果位宽

提供bit-accurate reference，即硬件可逐像素对照的定点黄金模型。

不要使用浮点OpenCV计算结果直接作为RTL逐像素正确性的唯一判据。

评估Dice、IoU、Precision、Recall与各样本失败情况。比较算法效果与预期硬件成本，选择最合理的一种。

如果传统算法效果不理想，说明局限，并提出硬件代价可控的改进方法；不要自行宣称达到医疗级分割精度。

## 6. FPGA RTL设计

目标输入：512×512，每像素32bit。

定义输入字节：
- Byte0：B
- Byte1：G
- Byte2：R
- Byte3：FOV有效标志

定义输出字节：
- Byte0：原始绿色通道
- Byte1：增强后灰度
- Byte2：血管分割掩膜，0或255
- Byte3：血管响应强度

必须实现或合理拆分以下功能：
- AXI4-Stream帧接收
- 绿色通道提取
- 高斯滤波
- 灰度增强
- 局部背景估计
- 血管特征提取
- 阈值分割
- 形态学后处理
- FOV掩膜控制
- 输出打包
- 帧计数及运行状态
- 控制寄存器

要求：
- 基于行缓存和滑动窗口。
- 流水线尽量实现II=1。
- 正确处理TVALID/TREADY反压。
- TDATA及所有帧控制信号严格对齐。
- Simple AXI DMA协议下正确生成帧末TLAST。
- 明确每个模块延迟。
- 不允许读取未初始化的行缓存数据。
- 支持连续帧输入且不会残留上一帧数据。
- 参数在帧边界同步更新。
- 提供pass-through和单级处理测试模式。

算法确定之前，优先构建简单可靠的流水线，不要一次写完全部复杂IP。

## 7. Vivado工程设计

先完成最小系统：

Zynq PS -> AXI DMA MM2S -> 自定义图像处理IP -> AXI DMA S2MM -> DDR

AXI4-Lite用于配置控制寄存器。

要求：
- 使用PYNQ-Z2正确的PS配置。
- 启用适合DMA访问DDR的PS HP端口。
- 使用AXI SmartConnect或兼容互连。
- 正确配置AXI DMA输入输出流宽度。
- 先使用Simple DMA模式。
- 选择合适的DMA长度寄存器位宽。
- 不要启用仅适合小数据块的Micro DMA模式。
- 生成.bit与.hwh。
- 使用Tcl脚本实现可重复构建。
- 输出综合、实现和时序报告。
- 禁止省略真实实现阶段而仅交付仿真结果。

先实现DMA loopback，通过之后再替换成图像处理IP。
