2026-10-14。Q1-r1的64组硬否决全部拒绝；Q1-r2的32组软惩罚中3组满足同一训练门槛，按预注册排序冻结 **C2_l9_d12345_m1_p28**。见[Q1实验报告](../results/q1_quality_2026-10-14/training_review.md)和[参数冻结记录](../results/q1_quality_2026-10-14/selected_candidate.json)。此处是实现规格，**尚无新RTL、综合资源、bitstream或板测性能**。

## 精确算法与复用边界

增强E、原响应A和后处理完全沿用已测A4。对每个E像素使用4方向、长度9、左右距离1/2/3/4/5的等长平行线，复制图像边界。任一方向/距离满足 `L-C>=9 && R-C>=9` 即有双侧支持。C/L/R范围0…2295，差使用有符号至少13位（现CPU用int16）。不将负差先截零，不用浮点均值或近似倒数。

新响应 `R = A`（有支持），否则 `R = max(0,A-28)`。该28是已冻结的局部惩罚，与用户可调整的分割阈值T是两个不同参数；正式对比仍T=28。后续 `R>=T`、原FOV、零边界CROSS闭运算、3×3计数≥2和最终原FOV按A4语义执行。禁止PS/浏览器再筛mask。

原算法A兼容路径必须保留；算法选择A/C2与现有stage mode0/1/2/3分开编码/显示，避免把原mode1、2叫成另一算法。mode0仍是原32位旁路，算法模式1–3输出仍为raw G、enhanced、当前stage mask、当前所选算法的response。新ABI/版本必须明确该响应字节含义。

复用 `hls/retina_segmentation_hls.cpp` 中已测Gaussian3/LUT、BoxFilter15、Threshold/morp_opr/Filter2D以及中心像素/FOV载荷；在新工作副本的 `response_carrier → threshold_binary` 之间加入实际PL支持判断/惩罚。新增特征来自同一增强E支路，不能从另一张图或上一帧借用结果。`software/q1_soft_support.py` 只作离线模型；`scripts/verify_q1_training.py` 的稠密整数相关实现已独立核对所选候选20个训练尺寸案例共3,276,800像素。

先查已安装2017.4 HLS Window/LineBuffer/Filter2D，保留安装头文件原件；现有标准PS/DDR/AXI DMA/GPIO/FIFO/guard/reset、PYNQ驱动和浏览器任务服务复用。优先共享19×19增强图窗口及重复中心线和；不能简单假定复制60个Filter2D实例的资源可接受。19×19是访问范围，不是实际资源/吞吐报告。

## 与W2共同实施

1. 冻结新ABI：算法A/C2、stage、256/512、阈值T、帧ID；首个输入握手锁存全帧，回读真实已锁存参数。复用标准AXI GPIO或厂商AXI-Lite模板，地址在BD审查后确认，不预填为已验证地址。
2. 新PL观测：首输入接受、末核心结果首次有效、末输出接受、输入空等和输出背压周期；硬件计数与软件任务绑定。DMA事务含PL重叠，纯DMA另用原A0回环，不能相减构造。
3. 先单独验证双侧支持/响应，再接入原A4后处理。扩展窗口使中心/原G/FOV/背景/response延迟变化，重新确定FIFO容量和有限流背压；不能盲用旧2048深度并仅凭Csim通过。需要厂商实际RTL多帧、256/512切换、边界、分叉/较粗血管/跨亮区合成输入、复位及长背压验证。
4. A模式T28逐字复现原61用例；C2模式对独立整数参考逐字一致。T边界1/27/28/29/255、帧中改参下一帧生效、无在途释放/重配继续测试。完成完整实现和资源/时序核对后才生成新的配对bit/HWH/发布包。
5. 真机先预检查→只加载→短帧→完整逐字验证，再接浏览器交互。交付时在对话中给出完整文件清单、代码框顺序、PASS标志和下载记录步骤。
