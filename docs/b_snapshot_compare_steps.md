# B 输出复制到普通 CPU 数组：对比步骤

上一轮缓存排版已完成实体板核验，完整核验/显示循环5.016FPS。本轮保留同一个缓存排版函数，比较直接读取DMA接收数组和“接收完成后复制一次到普通CPU数组”，复制后继续完整逐字核验、排版、哈希和官方显示。复制成本单独计入第2段，未修改官方分配/缓存/等待/VDMA代码；本轮板测NOT_RUN、提速NOT_MEASURED，不重跑原排版或旧完整测试。

1. 打开 `http://192.168.2.99:9090/tree`，显示器仍接板上 **HDMI OUT**。在 **Running** 页关闭之前已经成功完成的测试内核；尚未恢复的传输错误应保留输出和失败内核，先反馈。
2. 新建 **retina_b_snapshot_r1**。上传电脑 `D:\PLD\retina_fpga\build\deploy\b_snapshot_2017_4_r1` 中的 **全部22个文件**，完成列表中的Upload。仅打开 **b_snapshot_compare.ipynb**；两份旧Notebook是来源核对文件。
3. 依次运行以下7框，每框只运行一次：选中后 **Shift+Enter**，等 `In [数字]` 且无红色错误再继续。不要Run All。

|代码框|结束标志|观察|
|---|---|---|
|1：准备函数|`In [数字]`，无错误|没有打印正常。|
|2：检查文件和普通CPU数组|`B_SNAPSHOT_PRECHECK_PASS`|不加载FPGA。原缓存画布保留，另分配1MiB普通CPU暂存，接收之间只读；不分配原生DMA/视频帧。|
|3：加载一次|`B_SNAPSHOT_LOAD_PASS`|同一原B工程加载一次。|
|4：短帧和HDMI|`B_SNAPSHOT_HDMI_READY`|一帧256短测，显示蓝/绿/红彩条与白色定位线。正常后继续。|
|5：实际DMA复制与像素门禁|`B_SNAPSHOT_PIXELS_PASS`|一帧真实512输出：DMA/CPU暂存262,144字及4个标记的整幅720p图像一致，保存两份原数组。显示左原图、右绿色候选。|
|6：直接读与单次复制对比|`B_SNAPSHOT_COMPARE_COMPLETE`|先direct，再snapshot，每组3预热+30计时，每5帧打印进度。两组都保留完整核验/哈希/原生显示成本；打印包括CPU复制在内的11段平均ms。|
|7：关闭并打包|`B_SNAPSHOT_RESULTS_READY`|保存并关闭显示，网页显示最后一帧。显示器黑屏/无信号为预期。|

4. 第7框结束后 **Ctrl+S**，**File → Download as → Notebook** 下载执行后的 **b_snapshot_compare.ipynb**。
5. 回到同一文件夹列表下载 **b_snapshot_bundle.zip**，共含10个结果文件：原JSON、4份真实输出数组、彩条/门禁/最终图像。下载到Windows后反馈“已下载”，再独立复算两组时间、复制成本和实际改善。

红色报错或一分钟无新进展时保存输出并停止；不重复运行、不释放缓冲、不切换Overlay、不运行关闭框、不重启失败内核。原生接收/显示缓冲引用会在失败时保留。允许Notebook正常保存输出和日期；三个Notebook执行代码均严格核对，其余固定文件按SHA256核对。

本次共68算法帧，只有snapshot组在原接收wait完成之后进行一次np.copyto。暂存是普通NumPy数组，非原生帧缓存；两组使用同一算法缓冲对和相同缓存排版。每组30计时帧的完整循环包含复制成本、核验、算法/视频状态、官方帧分配/复制/刷新/中断等待/提交、哈希和进度。前置门禁、文件读取/参考生成/首次缓冲分配/预热以及最后PNG/NPY/JSON/ZIP保存不计入循环。板上旧日期保留，耗时用perf_counter_ns；扫描Hz、SD端到端、纯PL周期和CPU算法对比仍未验证。
