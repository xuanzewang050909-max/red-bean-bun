# B 分段性能诊断操作步骤

本次沿用已板测通过的 B r2 硬件、官方驱动、冻结算法和原排版函数，测量每个环节的耗时。交付时本次板测状态为 NOT_RUN。原 B 370 帧记录与显示照片已归档；本次新建文件夹保存诊断记录。

当前软件为分段诊断 r2，修正旧 B Notebook 保存后被完整文件哈希拦截的问题，两份 Notebook 均严格检查代码哈希。已上传 r1 并在第2框出现 `Profiling package mismatch: b_integration_check.ipynb` 时，按[预检查恢复步骤](D:/PLD/retina_fpga/docs/b_profile_precheck_recovery_steps.md)只替换3文件；此错误发生在FPGA加载前，可按恢复步骤重启内核。

1. 打开 Jupyter 首页：`http://192.168.2.99:9090/tree`。保持现有供电、网线，显示器接板卡 **HDMI OUT**。在 **Running** 页关闭之前已成功完成的 B 和其他控制 FPGA 的内核。若有尚未恢复的传输错误，先反馈，不直接关闭失败内核。
2. 新建文件夹，命名 **retina_b_profile_r1**。将电脑 `D:\PLD\retina_fpga\build\deploy\b_profile_2017_4_r2` 里的 **全部 17 个文件**上传进去，逐个点击 Upload 完成。文件夹里本次只打开 **b_performance_profile.ipynb**。已上传r1时沿用当前文件夹，按恢复步骤覆盖3文件即可。
3. 运行第 **1** 个代码框：选中后按 **Shift+Enter**。左侧由 `In [*]` 变成 `In [数字]`、没有红色报错，就表示导入完成；没有打印是正常的。
4. 运行第 **2** 框，等 **B_PROFILE_PRECHECK_PASS**。再运行第 **3** 框，等 **B_PROFILE_LOAD_PASS**。每次等当前框结束再运行下一框；第 3 框只加载一次 FPGA。
5. 运行第 **4** 框，等 **B_PROFILE_HDMI_READY**。此前还会打印原短帧校验和启动显示的标志。显示器应有蓝、绿、红彩条和白色定位线；确认显示正常再继续。
6. 运行第 **5** 框。先做 3 帧预热，再记录 **30 帧**；每 5 帧打印 `B_PROFILE_PROGRESS`。显示器会切到原图和绿色候选叠加，顶部白色标记随帧变化。最终出现 **B_PROFILE_COMPLETE**，并打印 10 个环节的平均毫秒数和占比。运行时间取决于实际板卡速度，待 `In [数字]` 且无错误后继续。
7. 运行第 **6** 框，等 **B_PROFILE_RESULTS_READY**。本框关闭官方显示、打包记录，并显示最后一帧预览；此时显示器变黑或提示无信号属于预期。按 **Ctrl+S** 保存。
8. 用 **File → Download as → Notebook** 下载运行后的 **b_performance_profile.ipynb**。回到同一文件夹列表，下载 **b_profile_bundle.zip**。两份文件下载到 Windows 后反馈“已下载”，由项目独立复算分段时间和实际输出。

任何代码框出现红色错误，或 **一分钟没有新进展**，保存输出并停止，反馈报错文字。不要重复运行当前框、释放缓冲、切换 Overlay 或运行关闭显示框；失败处理会保留可能仍在使用的缓冲引用。两份Notebook的自动保存允许改变输出和时间信息，执行代码仍严格匹配；脚本、配对 bit/HWH、输入、说明和manifest仍按固定字节哈希检查。

计时记录分别覆盖：算法 DMA/缓存/等待、逐字核验、字节数与帧计数、原 PS 排版、官方显示帧分配与检查、复制到显示帧、官方 writeframe 提交、视频状态、输出哈希、记录与进度打印。官方 writeframe 的缓存刷新和中断等待合并计入提交，不改底层缓存或驱动。另存整个循环的起止纳秒和少量计时簿记开销，逐帧分段之和须精确等于逐帧总时间。

这是固定 STARE 输入的分段诊断，输入文件读取、参考结果生成、初始算法缓冲分配、预热和最后保存文件不计入循环。板上旧日期原样保留，耗时使用 perf_counter_ns。30 帧的循环 FPS 是此次诊断负载下的测量；不代表新的优化结果、SD 读图到屏幕延迟、纯 PL 周期或显示器实际扫描 Hz。医学算法及质量结论沿用原冻结版本。
