# Q4d · C7板测步骤（主机发布检查完成，等待真实板测）

本轮是在PL内增加多尺度局部特征与固定树检测，针对残余亮边误检和细分支漏检；保留C5作真实同图对照。49项不同主机检查、实际RTL的17个独立完整帧与在途复位、100MHz完整布线及最终ZIP/Notebook配对解压检查均已通过。C7尚未板测，离线结果不能代替本轮。旧结果和失败日志不覆盖。新方案仍有亮带真血管损失和im0324等图像退化，是可选实验模式，不能据此宣布质量达标。

1. 打开Jupyter `http://192.168.2.99:9090/tree`。若旧实验已成功打印 `BROWSER_SERVICE_CLOSED_IDLE`，在Running页关闭它的旧内核；旧任务仍运行或FAULT时保留现场，不直接关闭/重载。服务使用8090，Jupyter使用9090。
2. 新建文件夹 `retina_q4d_c7_r1`，上传 `D:\PLD\retina_fpga\build\deploy\q4d_c7_upload_r1` 中两份配套文件：`q4d_c7_experimental_r1.zip`、`q4d_quality_start.ipynb`。不用手动解压ZIP，不混用旧Notebook，不覆盖旧目录。
3. 打开Notebook，从第1框顺序Shift+Enter；每框结束无红色报错再继续，不使用Run All。

|框|操作|完成标志|
|---|---|---|
|1|校验上传字节并解压|`PACKAGE_BYTES_PASS`|
|2|检查环境、保留端口|`BROWSER_PRECHECK_PASS` 和 `Q4D_PRECHECK_PASS`|
|3|只加载一次并启动服务|`BROWSER_SERVICE_READY`|
|4|自动采集20图×两尺寸×A/C2/C5/C7共160帧|`Q4D_COLLECTION_COMPLETE`，160个输出SHA匹配|

第4框期间不要在实验网页提交任务。匹配表示硬件实现与冻结参考一致，不能据此宣称医学质量达标。

4. 第4框结束后，打开 `http://192.168.2.99:8090/`，Ctrl+F5，确认页眉 **Q4d · C7**。固定 **512×512、最终掩膜模式3、快速无损PNG**。保持网页在前台，每次运行结束并更新图像后再操作下一项。

|顺序|图像|PL算法|阈值|
|---|---|---|---|
|1|im0001|C5|28|
|2|im0001|C7|112|
|3|im0002|C5|28|
|4|im0002|C7|112|
|5|im0324|C5|28|
|6|im0324|C7|112|

每项点一次“运行FPGA”并截图。切换算法会恢复各自推荐阈值；C7的112是新分数阈值，与C5的28含义不同。检查亮斑外沿的粗块误检、细分支连续性、经过亮区的真血管及页面硬件实际参数。

5. 选 **im0001/C7**，阈值 **96、128** 各运行一次；再选 **im0001/C5**，阈值 **20、36** 各运行一次。保持网页前台，等待每次绘制结束并检查回读。这里不改变固定160帧协议，也不覆盖旧T20隐藏页面记录。
6. 恢复 **im0001/C7/112**，点“预热3帧＋测量20帧”，保持网页在前台直至完成并截图。然后回Notebook运行第5框。按以上步骤预计 **completed=193**，应为 **READY / IDLE、pending=0、error=None、retained_buffer_count=0**。额外点击的合法任务保留，不为凑数重置。
7. 运行第6框，等 `Q4D_RESULTS_READY`；再运行第7框，等 `BROWSER_SERVICE_CLOSED_IDLE`。按Ctrl+S，File → Download as → Notebook下载运行后的 `q4d_quality_start.ipynb`，回文件列表下载同目录 `q4d_results_bundle.zip`。普通网页“导出会话”不能代替该固定队列包。

若红色报错或一分钟没有新进展，停在该框，保存输出和内核，不重复执行、重新加载或释放失败缓冲。关机/新内核后不可直接运行第5框：它需要第1–4框建立的同一个Python上下文。完成下载后反馈“已下载”及三图对照和20帧截图，项目再独立核对实际DMA所有字、PNG、参数/周期、计数与质量。

本轮是质量与交互诊断，保留后续W4正式性能、独立纯DMA、同PS CPU对照及W5稳定性实验。新硬件时延由这轮实测，不能沿用旧3.039ms；DMA事务包含流式PL计算，不能称纯搬运时间。
