本轮不录视频；等用户明确要求再安排。C7算法、bitstream、HWH、输入数组、原生DMA驱动、增强与分割数学未改。新展示流程尚为 **BOARD_NOT_RUN**。

上传文件位于 `D:/PLD/retina_c7_system/build/deploy/c7_showcase_r1/upload/`：

- `c7_showcase_r1.zip`

不要与旧c7_delivery_demo.ipynb混用，不手动解压。保留全部旧结果。旧服务正常完成并安全关闭后，在Jupyter Running关闭旧内核；若有FAULT/超时先保留现场，不关闭故障内核或自动重载。

## 七步操作

1. 打开 `http://192.168.2.99:9090/tree`，新建 `retina_c7_showcase_r1` 文件夹，上传上述两个文件，打开Notebook。运行第1框，看到 `SHOWCASE_PACKAGE_PASS`。已经成功的框不重复运行。
2. 运行第2框，看到 `SHOWCASE_PRECHECK_PASS`。要求SD至少1GiB空闲，8090可用；本框尚未加载FPGA。
3. 运行第3框，看到 `BROWSER_SERVICE_READY`，overlay只加载一次。
4. 运行第4框，再打开 `http://192.168.2.99:8090/`，Ctrl+F5确认页头 **DEMO R1 · C7**。完成下列短轮检查，期间保持网页前台，不刷新、不锁屏：
   - “全部20张”，512尺寸，点击“逐张运行当前列表”，等待20/20完成。每张发送新的PL任务，帧间停留2秒，约1～3分钟（依网络而变）。
   - 点击“上一张并运行”，完成后再“下一张并运行”，确认图号和任务号更新。
   - 切换256尺寸，运行一张；再恢复512。
   - “讲解样例8张”，点击逐张运行，检查8/8及每张说明。允许中途点击停止，当前帧正常收尾，不取消在途DMA；重新启动列表会从第一张新算。
   - 切到“功能演示（单独运行）”：`im0324_nogt / C7 / 最终 /112`显示未评价；`im0324 / C7 / 旁路 /112`只有原图，其余显示旁路无输出；`im0001 / C2 / 模式1 /28`和`模式2 /28`各一次。
   - 可再切回全部/样例继续展示。正常列表恢复C7最终T112。推荐流程35次，但**不要求恰好35或7次**；额外点击、停止后的已完成帧全部保留。单会话最多100次，逐张列表不会在剩余次数不足时启动。每帧提交前检查512MiB空间底线。
5. 等页面显示完成且无在途任务，回Notebook运行第5框，看到 `SHOWCASE_CLOSED_IDLE`。自动核对实际任务数与硬件序号，输出已观测/缺失观测列表。缺失观测不能算完整展示通过，但允许安全保存已完成证据。真实硬件FAULT禁止强制结束。
6. 运行第6框，看到 `SHOWCASE_RESULTS_READY`，生成 `c7_showcase_results.zip`。仅导出一次，不覆盖旧ZIP。
7. 运行第7框，确认CLOSED/IDLE、pending=0、error=None。Ctrl+S，将执行后的 `c7_showcase.ipynb` 和 `c7_showcase_results.zip` 下载到电脑Downloads；回复已下载。无需视频，也不重跑W4/W5长测。

错误或超时：停止后续点击，保留Notebook报错和浏览器状态；不刷新重试、重载bitstream或释放故障缓冲。若仅停止逐张列表，等待当前帧和绘制结束后，可安全继续自由展示或关闭导出。

## 回收与回滚

电脑运行 `scripts/verify_c7_showcase.py`，五个位置参数依次为下载ZIP、执行Notebook、发布Notebook、发布package、新结果目录；逐字核对每次输出及PNG、参数回读、计数、浏览器身份、CSV和关闭状态。分别报告20图/256与512/无标注/旁路/C2中间模式/缺失前台观测，不将样例选择当新质量测试。

本发布使用原C7硬件，无硬件回滚动作。若新版展示有问题，保存现场，正常结束后回到原 `c7_delivery_demo_r1` 配对Notebook与W5b ZIP，在全新目录启动，沿用其原七次规则；旧发布物没有覆盖。
